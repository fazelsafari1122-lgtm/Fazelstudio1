# Fazelstudio — ماژول‌های جدید (مدیریت آتلیه)

## اجرا
```bash
npm install
npm run dev        # http://localhost:3000
npm test           # تست‌های بک‌اند و رابط
```
داده‌ها در `./data` (SQLite) ذخیره می‌شوند؛ مسیر را می‌توان با `DATA_DIR` تغییر داد. در اولین اجرا داده نمونه فارسی ساخته می‌شود
(۳ شعبه، ۵ سالن، ۲۰ خانواده، حدود ۵۰ عضو، ۲۴ نوبت، ۲۰ پروژه، فاکتور، پرداخت، چک، هزینه، پیگیری، پیامک، کالا).

## چه چیزهایی اضافه شد
| بخش | مسیر | توضیح |
|---|---|---|
| مدیریت خانواده‌ها | `#/customers`, `#/customers/:id` | پدر، مادر، فرزندان نامحدود، تگ، جستجوی لحظه‌ای (نام/موبایل)، پرونده کامل با بدهی |
| نوبت‌دهی | `#/appointments` | روزانه/هفتگی/ماهانه شمسی، شعبه و سالن، Slot قابل تنظیم، جلوگیری از تداخل، تعطیلات، ساعات کاری، بیعانه آنلاین (شبیه‌سازی) |
| مدیریت پروژه | `#/projects`, `#/projects/:id` | Kanban با Drag & Drop (ستون‌های قابل تنظیم) + جدول |
| آماده‌سازی عکس/فیلم/آلبوم | `#/projects/preparation/{photo,video,album}` | مراحل، مسئول، Deadline؛ اتمام همه مراحل ⇒ پروژه «آماده تحویل» |
| پیگیری مشتریان | `#/followups` | انجام شد / پیگیری بعدی / بستن، «پیگیری‌های من» در Header |
| چک‌ها | `#/cheques` | چک برگشتی مبلغ را از پرداخت‌ها کسر و پیگیری فوری می‌سازد |
| کالاها | `#/products` | موجودی، حداقل موجودی، تاریخچه افزایش/کاهش |
| هزینه‌ها | `#/expenses` | CRUD کامل، دسته‌بندی‌های قابل مدیریت، نمودار سهم دسته‌ها |
| پیامک | `#/sms`, `/sms/queue`, `/sms/sent`, `/sms/templates` | قالب با `{{نام}} {{مانده}} ...`، صف، زمان‌بندی، ارسال مجدد، ارسال گروهی |
| فاکتور | دکمه «فاکتور جدید» در مدیریت فاکتورها | آیتم، تخفیف، هزینه اضافه، مالیات؛ مبلغ نهایی − پرداخت = مانده |
| داشبورد مدیریت / گزارش‌ها | `#/management`, `#/reports` | همه اعداد از داده واقعی؛ نمودار روز/هفته/ماه/سال؛ خروجی CSV (اکسل) |
| اطلاعات پایه | `#/basic-information` | شعبه، سالن، خدمات، پکیج، دسته‌بندی‌ها، بانک‌ها، وضعیت پروژه، تگ، قالب پیامک، پرداخت آنلاین |
| کاربران و دسترسی‌ها | `#/users` | نقش‌ها: مدیر، حسابدار، اپراتور، عکاس، ادیتور؛ ماتریس دسترسی |

همچنین: جستجوی سراسری و مرکز اعلان‌ها در Header، Sidebar جمع‌شونده (حالت ذخیره می‌شود)، مسیرها با hash (بعد از Refresh حفظ می‌شود).

## معماری
```
src/services/api.ts + studioApi.ts   ← تنها نقطه ارتباط با سرور (قابل جایگزینی)
server/routes/*.ts                   ← لایه سرویس (خانواده، نوبت، پروژه، مالی، پیامک، گزارش ...)
server/finance.ts                    ← محاسبه مانده فاکتور/قرارداد، بدهی
server/smsGateway.ts                 ← اینترفیس درگاه پیامک (Mock؛ برای درگاه واقعی پیاده‌سازی کنید)
server/extraSchema.ts                ← مهاجرت‌های افزایشی دیتابیس
```
- احراز هویت اکنون با نشست (session) واقعی است و همه `/api/*` (به‌جز ورود و `/api/public/*`) توکن و دسترسی می‌خواهند.
- درگاه پیامک و پرداخت آنلاین «آزمایشی» هستند؛ ساختار آن‌ها برای اتصال به سرویس واقعی آماده است.
- چک: چک جدید هنگام ثبت در «پرداخت‌ها» حساب می‌شود؛ با «برگشتی» شدن، پرداخت مربوطه حذف و بدهی برمی‌گردد.

## نکات مهم
- در `LoginView.tsx` اطلاعات ورود پیش‌فرض مدیر داخل فرم پر شده است؛ قبل از استقرار رمز را تغییر دهید و مقدار پیش‌فرض را حذف کنید.
- ویرایش/حذف فاکتور مستقل (بدون قرارداد) در API موجود است (`PUT/DELETE /api/invoices/:id`)؛ در رابط، فعلاً فقط ثبت فاکتور جدید در دسترس است.
- خروجی «اکسل» فایل CSV با BOM است که مستقیماً در Excel باز می‌شود.
